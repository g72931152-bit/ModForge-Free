# ModForge — готовый one-service проект

ModForge — веб-сервис для проверки и безопасного исправления ZIP-модов BeamNG. В этой сборке frontend и FastAPI backend находятся в одном Docker-сервисе, поэтому после публикации на Render не нужно вручную прописывать URL backend.

## Что реально работает

- drag-and-drop ZIP;
- загрузка ZIP в FastAPI с потоковой записью на диск;
- лимит входного архива 2 ГБ (настраивается через `MAX_UPLOAD_BYTES`);
- защита ZIP от path traversal;
- ограничение распакованного размера для защиты от zip-bomb (`MAX_UNCOMPRESSED_BYTES`);
- статический анализ JSON/JBeam/PC/materials;
- поиск ссылок на DDS/PNG/JPG/TGA/BMP/DAE/CDAE/JBeam/PC/JSON;
- поиск отсутствующих ресурсов;
- исправление однозначно сопоставимых путей и регистра ссылок;
- пересборка `_FIXED.zip`;
- JSON-отчёт;
- веб-страница отчёта;
- health endpoint `/api/health`;
- frontend и API на одном адресе;
- Dockerfile находится **в корне репозитория**, чтобы Render мог собрать проект без дополнительных Root Directory настроек.

## Важное про бесплатный Render

Render действительно имеет бесплатный Web Service, но бесплатные сервисы засыпают после 15 минут бездействия и имеют ограниченные CPU/RAM. Кроме того, файловая система без persistent disk эфемерная: файлы в ней теряются при перезапуске/деплое. Поэтому эта сборка предназначена для старта и тестирования. Для постоянного хранения пользовательских ZIP понадобится отдельное объектное хранилище, а для тяжёлого анализа — более мощное окружение.

Для бесплатного запуска не добавляй Environment Variables: всё необходимое имеет безопасные значения по умолчанию.

## Render

В твоём существующем Web Service:

- Language: `Docker`
- Branch: `main`
- Root Directory: пусто
- Dockerfile Path: `./Dockerfile`
- Compute: `Free`
- Environment Variables: пусто

После обновления GitHub Render автоматически запустит новый deploy.

## Локальный запуск

### Windows

```text
start_backend.bat
```

### Linux/macOS

```bash
./start_backend.sh
```

Затем открой `http://127.0.0.1:10000`.

## Smoke-test


## Ограничения, которые намеренно не скрываются

Эта версия действительно анализирует и исправляет файлы, но не запускает сам BeamNG. Поэтому она не может честно определять глазами движка такие вещи, как «стекло визуально выглядит плохо», физически неверный UV или реальное освещение в игре. Для этого предусмотрен отдельный BeamNG/headless renderer, который можно подключить позже.

## Монетизация

В интерфейсе предусмотрены места под рекламу, поддержку автора и будущие дополнительные функции. Не встраивай рекламные/платёжные ключи прямо в GitHub: секреты должны храниться в переменных окружения или в панели соответствующего сервиса.
